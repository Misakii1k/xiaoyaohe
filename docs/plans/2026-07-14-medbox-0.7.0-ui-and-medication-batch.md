# 日常工具箱 0.7.0 全面屏前端重构与批量药品录入 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task.

**Goal:** 在不削弱既有医疗安全、隐私、安全和离线能力的前提下，完成适配 Android 全面屏的中文 UI 重构，并交付原子化批量录药、低打扰 AI 辅助与可管理的品牌资源体系。

**Architecture:** 采用 `app / core / ui / modules` 的分层架构：应用壳统一负责安全区、导航和页面生命周期；`ui` 只提供无业务依赖的令牌与可访问原语；药品、扫描、工时和设置各自经公开模块接口接入。批量录药以可累积草稿和一次 IndexedDB 事务为边界，图片识别只追加草稿，最终由用户一次保存全部内容。

**Tech Stack:** TypeScript、Vite、Vitest、Playwright、IndexedDB/idb、Capacitor 8、Android、`@capacitor/local-notifications`、`lucide`（锁定本地 npm 依赖）、现有 Cloudflare Worker 与 PWA 构建链。

## 1. 总目标

在保留现有吃药、扫码、工时、设置、同步和发布能力的前提下，完成一轮面向 Android 全面屏与 PWA 的前端架构重构，并交付以下结果：

1. 修复系统状态栏覆盖应用顶栏、底部手势区遮挡导航、横屏安全区失效等问题。
2. 把现有高模糊、大圆角、大字号、卡片堆叠的界面改为清爽、可信、紧凑的中文日常工具界面。
3. 将吃药与工时合并到统一的五栏导航：`今日 / 药品 / 扫描 / 工时 / 设置`。
4. 将“新增药品”改为统一新增工作台：默认一条药品，可增加空白项或通过多张图片追加多条，最后一次保存全部。
5. 将不常用字段折叠；常用字段和 AI/拍照入口放在最前面。
6. 降低 AI 外发授权和剂量确认的重复弹窗，同时维持医疗数据边界与库存正确性。
7. 建立品牌 Logo、应用图标、功能图标、插画、生成源文件和生产资源的完整管理规范。
8. 拆分应用壳、设计令牌、基础组件、业务模块和页面样式，为后续新增工具留出稳定扩展接口。
9. 通过前端、Worker、Android、响应式、无障碍、真机和发布流水线门禁，生成 0.7.0 验收产物。

### 4.2 依赖方向

- `app` 可以依赖 `ui`、`core` 和各模块公开的 `index.ts`。
- `ui` 不得依赖任何业务模块。
- 单个业务模块只能依赖 `core`、`ui` 和自身内部文件，不得导入另一个模块的内部路径。
- 跨模块能力通过公开接口或 `moduleRegistry` 连接。
- 0.7.0 不强制移动所有旧数据文件；`src/db` 可以暂时保留，由模块 infrastructure 层包装。
- 旧页面可先成为薄兼容导出，完成迁移后再删除，避免一次性大范围 import churn。

### 4.3 模块注册接口

```ts
export interface AppModule {
  id: string;
  title: string;
  routes: Array<{ path: string; handler: RouteHandler }>;
  navItem?: { label: string; icon: AppIconName; href: string; order: number };
  backupProvider?: BackupProvider;
  getSummary?: () => Promise<ToolSummary>;

```

- 后续新增工具只能注册 `AppModule`，不得直接在 AppShell 内硬编码页面实现。
- 五个 0.7.0 导航项仍由 `navigation.ts` 显式排序，避免未来模块自动把底栏撑满。
- 新模块超过五个后，非高频工具进入设置中的“更多工具”，不自动新增底栏入口。

## 5. 全面屏与应用壳方案

### 5.1 根因

- Android `targetSdkVersion=36` 强制 edge-to-edge。
- Capacitor 8 `SystemBars` 会注入 `--safe-area-inset-top/right/bottom/left`。
- 当前 CSS 只使用 `env(safe-area-inset-*)`；用户设备上该值为 0，导致应用顶栏进入系统状态栏。
- 相同缺陷同时影响底部导航、批量操作栏、FAB、Toast、弹窗和横屏。

### 5.2 安全区令牌

```css
:root {
  --safe-top: max(env(safe-area-inset-top, 0px), var(--safe-area-inset-top, 0px));
  --safe-right: max(env(safe-area-inset-right, 0px), var(--safe-area-inset-right, 0px));
  --safe-bottom: max(env(safe-area-inset-bottom, 0px), var(--safe-area-inset-bottom, 0px));
  --safe-left: max(env(safe-area-inset-left, 0px), var(--safe-area-inset-left, 0px));
}
```

- 除 `tokens.css` 外禁止直接使用 `env(safe-area-inset-*)` 或 Capacitor 原始变量。
- `AppShell` 使用 `height: 100vh; height: 100dvh; display:grid`。
- 网格行固定为：安全区顶栏、可滚动正文、导航安全区；正文使用独立滚动容器。
- 页面固定操作栏必须占据 shell 的 action-dock 插槽，不得覆盖正文。
- 弹窗、底部面板、扫码相机和 Toast 全部消费四个统一安全区令牌。

### 5.3 原生配置

- `capacitor.config.ts` 增加 `SystemBars: { insetsHandling: 'css', style: 'LIGHT', hidden: false }`。
- Android runtime theme 改为浅色 NoActionBar，状态栏和导航栏采用浅色背景深色图标。
- Android 15/16 不使用固定 24px 补丁，不关闭 edge-to-edge。
- 系统主题切换不改变本轮 Web 浅色主题；系统栏始终保持足够对比度。

## 6. 基础组件规范

- `Button`：主操作、次级、危险、文字四种语义；按钮内部文本最多两行，命令优先图标+短中文。
- `IconButton`：仅图标、44px 触控区、必须提供中文 `aria-label` 和 tooltip。
- `SegmentedControl`：用于扫描模式、列表视图等互斥选择，不用于普通命令。
- `Accordion`：使用原生 `details/summary` 或等价可访问实现；关闭后内部控件不得进入 Tab 顺序。
- `BottomSheet`：用于扫描结果、批量时段菜单和移动端选择；支持 Esc、遮罩关闭、焦点陷阱和恢复焦点。
- `ActionDock`：位于 AppShell 正文下方、导航上方；高度可测量，不覆盖内容。
- `FormField`：统一 label、描述、错误、`aria-describedby`、必填标记和焦点行为。
- `StatusBadge`：状态文本必须明确，例如“待服”“已服”“需复核”，不允许只显示色点。
- 所有页面只组合这些组件，不自行复制弹窗、按钮、折叠区和底部操作栏逻辑。

- 增加固定版本的 `sharp` 开发依赖，建立 `npm run assets:build` 和 `npm run assets:check`。

## 10. 批量药品数据模型与事务

### 10.1 草稿类型

```ts
export interface MedicationCreateDraft {
  id: string;
  medication: Medication;
  rules: DraftReminderRule[];
  sourceKind: 'manual' | 'medicine-box' | 'prescription';
  sourceImage?: File;
  confidence?: number;
  selected: boolean;
  expanded: boolean;
  duplicateResolution?: 'skip' | 'create';
  errors: Array<{ field: string; code: string; message: string }>;
}
```

- 草稿创建时立即生成稳定 UUID；重试保存不得换 ID。
- AI 数据只填入草稿，不直接落库。
- 同批次和数据库已有药品按规范化药名、规格、GTIN 和原始码检测重复。
- 疑似重复项必须选择“跳过”或“仍新建”；本轮不在批量新增中自动更新已有药。

### 10.2 原子保存接口

```ts
export async function createMedicationBatch(
  drafts: readonly MedicationCreateDraft[],
): Promise<{ medIds: string[]; reminderRescheduleRequired: boolean }>;
```

- 一个 IndexedDB `readwrite` 事务覆盖 `meds`、`rules`、`scheduleRevisions`、`photos` 和 `outbox`。
- 任意药品、规则、revision、照片或 outbox 写入失败，整个事务回滚。
- 处方/药单图片只在内存中用于审核，不持久化，减少健康文档泄露和重复占用。
- 单药盒图片可以压缩后作为该药品识别证据持久化。
- 提醒重排在事务提交后执行一次；失败仅显示可重试警告，不回滚已保存数据。
- 保存按钮在运行时禁用；成功后清除草稿并返回药品列表。

### 10.3 校验顺序

1. 选中项数量大于 0。
2. 药名非空且长度在运行时 schema 范围内。
3. 结构化剂量的数值和单位成对出现。
4. 每个选中时段都有合法 `HH:mm`。
5. 周期开启时 active/rest days 和本地周期首日合法。
6. 有效期为合法本地日期。
7. 库存数值非负，单位与结构化剂量兼容时才允许自动扣减。
8. 重复项已经明确处理。
9. 常见相互作用提示按整个批次汇总一次。

## 11. 批量图片识别

- 相册输入允许 `multiple`；相机每次拍一张并追加到当前队列。
- 限制：最多 10 张、原始总大小 30MB、单图 12MB、仅接受可解码图片。
- 每张图片先压缩到最长边 1280、JPEG 质量 0.8，再发送给 AI。
- 同时最多 2 个请求；同一批次只进行一次健康数据授权预检。
- 单图最多接受 20 个 items，整批最多 50 条草稿；超量返回可恢复错误。
- 每个响应使用运行时 schema 校验并截断超长字段；无效 JSON 不创建草稿。
- 图片失败只标记该图片；重试只重跑失败图片。
- 路由切换后 AbortSignal 停止等待请求和未启动队列，旧页面不得更新 DOM 或 toast。
- 多图结果通过稳定草稿 ID 合并；重复项仅标记冲突，不自动覆盖。

## 12. AI 授权优化

```ts
type AiConsentCategory = 'health' | 'work';
interface StoredAiConsent {
  version: 2;
  origin: string;
  category: AiConsentCategory;
  grantedAt: number;
}
```

- `medicine-photo` 和 `prescription` 合并为 `health`；工资和工时属于独立的 `work`。
- 首次向某个 HTTPS origin 发送某类别数据时明确显示目标域名并确认。
- 授权写入 `localStorage`，直到用户撤销、origin 变化或 consent schema version 变化。
- API key 存储策略不变：Android 安全存储，PWA 当前会话内存。
- 批量识别在队列启动前确认一次，不逐图确认。
- 已授权时在 AI 操作旁显示非阻塞文字“将发送至 example.com”，不弹窗。
- 设置页提供按类别撤销和全部撤销；撤销不删除 API key。
- HTTP、含凭据 URL、localhost 生产地址和无效 origin 继续阻断。

## 13. 剂量确认优化

- 新增确定性解析函数，只接受明确格式，不调用 AI 猜测。
- 支持：`1片`、`0.25片`、`1.5粒`、`5mL`、`5 ml`、`半片`、`1/2片`。
- 支持单位白名单：片、粒、袋、支、丸、滴、喷、mL/毫升；单位标准化但保留原始文本。
- 不把 mg、规格、包装数量误认为每次剂量；不做片数与毫克之间换算。
- 解析成功后在字段下内联显示“已识别：每次 0.25 片”，直接填充结构化字段，不再弹确认框。
- AI 返回的剂量在草稿主要区域高亮；用户点击一次“保存全部”视为对可见草稿的统一审核。
- 解析失败时保存为 `doseReviewRequired=true`，内联显示“剂量未结构化，库存不会自动扣减”，但不再弹二次确认框。
- 编辑剂量后实时重新解析；库存单位不兼容时显示错误并禁止自动扣减。

## 15. 自动化测试清单

### 15.1 架构与资产

- 模块只能遵循约定的 import 方向。
- 页面不得直接创建通用 SVG 图标或绕过 icon registry。
- 除 tokens.css 外不得直接使用 safe-area env 或品牌硬编码色。
- 所有生产图片都存在于 assets manifest，尺寸和哈希一致。
- Lucide 许可证和版本被记录，生产构建不访问图标 CDN。

### 15.2 全面屏与布局

- 顶栏可点击元素的 top 坐标不小于系统安全区。
- 正文可滚动区域的 bottom 不被 ActionDock 或导航覆盖。
- 横屏左右安全区生效，BottomSheet 不进入挖孔区。
- 320px 下药品批量行名称至少获得除复选框外的可用宽度，标签在下一行换行。
- 200% 缩放时无水平页面滚动，操作按钮和后续内容不重叠。

### 15.3 批量新增

- 默认一条草稿；删除最后一条后自动保留空白草稿。
- 手工新增三条，其中一条无效时数据库零新增。
- 修正后一次产生三条药、对应规则/revision/outbox，提醒只重排一次。
- 任一事务 store 写入失败整批回滚。
- 疑似重复未处理时禁止提交；选择跳过后只保存非重复项。
- 保存成功但提醒重排失败时刷新仍能看到唯一药品，不重复创建。

### 15.4 图片与 AI

- 单张图识别多药；三张图结果累积。
- 第二张图失败不清空第一和第三张；重试只发送第二张。
- 第 11 张图片、总大小超限、无效图片、超量 items、无效 JSON 均可恢复。
- 切页后不继续启动请求、不写旧 DOM、不弹旧 toast。
- 同一 health origin 只首次确认；work 类别独立确认；origin 改变后重新确认。
- 撤销授权后下一次请求重新显示目标域名。

### 15.5 剂量与医疗边界

- 1片、0.25片、1.5粒、5mL、半片、1/2片得到正确结构化值。
- 100mg/片、30片/盒、每日一次不得被误认为每次剂量。
- 含糊剂量无弹窗、标记需复核、库存不自动扣减。
- AI 剂量在保存前始终可见并可编辑。
- 过期药、相互作用提示、到点校验、跳过统计和库存事务保持现有测试通过。
