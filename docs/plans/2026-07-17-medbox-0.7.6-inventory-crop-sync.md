# Medbox 0.7.6 计划：药库存页 + 药盒本地裁切 + 加密家庭同步

> 2026-07-17 后续决定：第 3 部分的 PWA/Worker 云同步只代表 0.7.6 已完成的历史实现，不再是后续产品方向。0.7.7 起只交付 Android App，家庭同步改为同一局域网内一次扫码直连。新方案、数据边界和实施门槛见 `2026-07-17-medbox-0.7.7-app-lan-sync-design.md`。

## Context

当前版本 **0.7.5**。本次在同一版本迭代里做三件事（用户已确认范围）：

1. **药库存界面**：查看剩余量、是否该补货；**不新增底栏 Tab**，从药品列表顶栏进入，路由 `/meds/inventory`。
2. **药盒照片**：取消 AI 生图/修图；改为「扫描全能王」式 **本地自动检测四角 + 可调裁切**（仅药盒照片入口）。
3. **加密家庭同步 v2**：客户端 UI 与 Worker **一并打开**（去掉灰度关闭）。

已有可复用基础，无需新数据模型：

- 库存域：`src/features/inventory.ts`（扣减、可用天数、低库存阈值）、`inventoryReminder.ts`
- 药品字段：`Medication.inventory`（`remaining` / `unit` / `packageQuantity` / `lowThreshold` / `dailyConsumption`）
- 编辑页已可填库存；打卡 `local.ts` 已扣减/恢复库存
- 药品列表仅展示「约还够 N 天」标签
- Sync v2 协议/客户端/Worker 已实现，仅开关关闭

版本发布规则：升到 **0.7.6** / Android `versionCode 13`，大白话更新说明，改完提交，打包桌面 APK。

## 一、药库存页：要展示什么（信息架构）

### 入口与导航

| 项 | 约定 |
|---|---|
| 路由 | `/meds/inventory`（在 `registry` 里**注册在** `/meds/:id/edit` **之前**，避免被当成 id） |
| 入口 | 药品列表顶栏 pill：**库存** · 批量管理 · 添加药品 |
| 壳 | `renderPage({ title: '药库存', activeTab: 'meds', topLeft: 返回药品 })` |
| 底栏 | 仍 5 项，**不**加 Tab |

### 页面结构（对齐 MedList 视觉）

1. **顶部摘要条**（一排数字，非营销大卡）
   - 在管药品数
   - 低库存数
   - 已用完数
   - 未设置库存数
2. **搜索**（药名，防抖同药品列表）
3. **筛选 chips**（横滑，同 `.medication-filter-*`）
   - 全部
   - 低库存（`remaining <= threshold`）
   - 已用完（`remaining <= 0` 且有库存记录）
   - 未设置（无 `inventory`）
   - 快见底（有 `estimateDaysLeft`，且 ≤ 7 天；可与低库存重叠）
4. **列表**：单块白底圆角列表（复用/镜像 `.medication-list` + row，**禁止卡套卡**）

### 每一行内容

- 左：药盒缩略图或 `box` 图标 tint
- 中：
  - 药名
  - 副行：`剩余 12 片 · 每次 1 片 · 约还够 6 天`（缺字段则省略对应段）
  - 标签：
    - `库存不足` / `已用完` / `未设置库存`
    - `约还够 N 天`（≤3 天 warn）
    - 若有整盒量：`一盒 30 片`
- 右：编辑入口（进 `/meds/:id/edit`，落在库存区块即可）

### 行点击 / 快捷操作（BottomSheet，文案大白话）

- **补一盒**：`remaining += packageQuantity`（无整盒量时先提示去编辑页填「一盒有多少」）
- **设为整盒**：`remaining = packageQuantity`
- **改剩余**：数字输入后 `putMed`
- **标记用完**：`remaining = 0`
- **完善库存**：无库存时 → 编辑页

操作后 toast + 刷新本页列表与摘要。

### 空状态

- 一个药都没有：`emptyState('box', '还没有药品', '…', 按钮「去添加药品」)`
- 有药但筛选无结果：文案「没有符合条件的药」+ 清筛选

### 逻辑复用（避免两套阈值）

在 `inventory.ts` 抽出：

- `getLowStockThreshold(med)`（与 `deductInventory` / `shouldSendLowStockReminder` 同一默认：`lowThreshold ?? max(1, ceil(packageQuantity*0.2))`）
- `isLowStock(med)` / `classifyInventoryStatus(med, rules)` → `'unset' | 'empty' | 'low' | 'ok' | 'days_low'`

列表排序建议：已用完 → 低库存 → 快见底 → 正常 → 未设置；同组按药名。

### 不做（本版）

- 不新建库存历史表
- 不改打卡扣减规则
- 不做扫码入库流水线
- 不把工时相关数据混入库存

## 二、药盒照片：去掉 AI 修图，改本地检测裁切

### 用户路径

拍/选药盒图 → **自动找药盒大致四角** → 底部裁切确认（可拖四角）→ 确认后透视裁切 → 现有 `compressBoxPhoto` → 预览/入库。

取消、检测失败：默认整图内缩框或「用整张图」。

### 删除 AI 图像模块

| 动作 | 路径 |
|---|---|
| 删除 | `src/ai/imageGen.ts`、`tests/imageGen.test.ts` |
| 清引用 | `MedEdit.ts` 全部 `refineBoxPhoto` / `isImageGenConfigured` / 「AI 优化图片」按钮与 sheet 项 |
| 清设置 | `Settings.ts`「图像 AI」整块；保存/重置里的 `setImageGenConfig` / `resetImageGenConfig` |
| 清密钥 | `secretStore.ts` 的 `IMAGE_SECRET_KEY` 及相关读写（若仅图像用） |
| 可选清理 | 启动时 `localStorage.removeItem('medbox.imageGenConfig.v1')` 一次，避免脏配置 |
| 保留 | 文字 LLM、药盒识别 `identify`、处方解析、`compressBoxPhoto`、照片 IDB |

### 新模块（纯本地，不引入 OpenCV 包）

1. **`src/features/boxPhotoCrop.ts`**
   - 输入 `Blob`，缩放到检测用边长（如最长边 ≤ 960）降内存
   - 简易文档检测：灰度 → 模糊 → 梯度/边缘 → 找近似四边形轮廓；失败返回 null
   - `warpPerspectiveQuad(blob, corners) → Blob`（canvas 三角形剖分双线性即可，实现自写）
   - 单元测试：构造纯色矩形图，期望检测框大致覆盖；`warp` 输出非空 JPEG

2. **`src/ui/BoxPhotoCropSheet.ts`**
   - BottomSheet / 全屏编辑层（z-index 与现有 sheet 一致，≥240）
   - 显示原图 + 可拖四角控制点 + 连线
   - 按钮：**确认裁切** / **用整张图** / **取消**
   - 确认后返回裁切 Blob

3. **`MedEdit` 编排**
   - `file`/`camera` 选图后：`openBoxPhotoCropSheet` → 成功则 `prepareBoxPhoto(cropped)` → 现有预览与保存
   - 按钮文案：**裁切药盒图**（有图时 sheet：重拍 / 重新裁切）
   - **不**改小助手附件、分药扫码、批量识别拍照

### 性能与安全

- 检测与 warp 前先缩小；最终仍走 `compressBoxPhoto`（720 / ~220KB）
- 无网络、无密钥、不进 AI consent

## 三、加密家庭同步：客户端 + Worker 打开

### 现状

- UI：`Settings.ts` 中 `SYNC_V2_UI_ENABLED = import.meta.env.VITE_SYNC_V2_ENABLED === 'true'`，现为关 → 显示「灰度关闭」
- Worker：`wrangler.toml` 中 `SYNC_V2_ENABLED = "false"`，`SYNC_V2_ALLOWED_ORIGINS = ""` → 任意请求 fail-closed 503
- 协议、配对、加密、DO 已实现（见 `src/sync/v2/*`、`worker/routes/sync-v2.ts`）

### 改动

1. **客户端构建**
   - 增加/启用 env：开发用 `.env` 或 `.env.production`：
     - `VITE_SYNC_V2_ENABLED=true`
     - 可选 `VITE_SYNC_V2_ENDPOINT=https://<你的-worker域名>`（若设置页需要默认服务地址；否则用户手填）
   - 设置页去掉「灰度关闭」死面板，走现有 `renderSyncV2Body`（创建家庭 / 配对 / 立即同步 / 设备管理）

2. **Worker `wrangler.toml`**
   ```toml
   SYNC_V2_ENABLED = "true"
   SYNC_V2_ALLOWED_ORIGINS = "https://localhost,http://localhost,http://127.0.0.1:<dev-port>,https://<pages-域名>"
   ```
   - **禁止 `*`**（代码会拒绝）
   - 空 allowlist 仍等于不可用
   - Capacitor：`androidScheme: 'https'` → Origin 通常为 **`https://localhost`**
   - PWA：必须把实际 Pages 域名写进 allowlist
   - 生产域名以部署时 `wrangler` / Cloudflare 控制台为准；**仓库内若无固定域名，实现时用占位并在注释与设置帮助文案写清「Origin 必须完全一致」**

3. **部署动作**（实现后执行）
   - `npm run worker:deploy`（或项目既有脚本）使 Worker 变量生效
   - 客户端 `android:debug` / Pages 构建带上 `VITE_SYNC_V2_ENABLED=true`

4. **文案**
   - 去掉「灰度关闭」
   - 保留安全说明：端到端加密、工时收入不同步、恢复码离线保存、PWA 会话凭证限制

### 本版不做

- 不重写 v2 协议
- 不打开 v1 `/api/sync`（保持禁用）
- 不把工时纳入同步
