小助手重设计 · 三个方向

现状问题：助手面板是「白色聊天气泡窗」，与应用整体的冰白底 + 微卡片 + 青绿体系是两套语言。以下三个方案共用同一套设计令牌与内容数据，仅视觉方向不同。点卡片打开完整原型，每个原型右上角可切换深色预览。

方案 A · 秩序文档 改动最小

去掉聊天软件外壳：助手回复以文档流直接落在冰白底上，头部、卡片、输入条全部复用页面语言。克制、工具感、零割裂。

去气泡文档流风险最低

方案 B · 盒宝伙伴 人格化

吉祥物「盒宝」成为助手的人格载体：头部立像、欢迎 hero 卡、每条回复带小头像，与打卡弹窗、空状态的盒宝插画体系闭环。

盒宝立像欢迎卡温暖陪伴

方案 C · 水凝玻璃 材质感

助手是浮在应用之上的一层玻璃：面板、气泡、输入条统一半透明磨砂，透出背后的今日页，与底栏、弹层同一材质语言。

半透明磨砂悬浮输入条轻盈高级
三个方案共享的底线：全部走 tokens.css 设计令牌（浅色/深色自动适配）；触控热区 ≥ 44px；时段/状态胶囊防折行；动效遵守 prefers-reduced-motion；结构化卡片（统计格、药品清单行）三方案完全一致，只是承载材质不同。确认方向后，也可混搭（如 A 的文档流 + B 的盒宝头像）。
